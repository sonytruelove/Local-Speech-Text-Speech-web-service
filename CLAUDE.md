# voice-echo-service — конвенции для агентов (code-gauntlet)

Tier: **standard** (внутренний локальный инструмент одного пользователя, не критичный путь;
но Stage 3a security baseline обязателен без смягчения, т.к. сервис принимает внешний
вход — HTTP API, загрузка аудио).

## Конвенции кода

- Функции: 4–20 строк, одна ответственность.
- Файлы: до ~200–300 строк; если больше — разбивать по ответственности.
- Имена: уникальные, самоописательные.
- Типы: явные везде (type hints обязательны, `Any` — только с обоснованием в комментарии).
- Вложенность: максимум 2 уровня (early return вместо вложенных if).
- DRY: не копировать логику; выносить в общую функцию при втором повторении.
- Dependency Injection: STT/TTS-бэкенды передаются в приложение как реализации `Protocol`,
  а не создаются внутри обработчиков — тесты подставляют fake-реализации.
- Ошибки: сообщение содержит контекст и фактические значения, не generic "invalid input".
- Форматирование: `ruff format` обязателен перед коммитом.

## Тесты

- Команда запуска: `pytest` (из venv `.venv`), без ручной подготовки окружения.
- Реальные модели (faster-whisper, Piper) в юнит/API-тестах не используются — только
  fake-реализации `SpeechRecognizer`/`SpeechSynthesizer` (детерминированные, без сети).
  Тест с реальными моделями — отдельный `@pytest.mark.real_models`, skip по умолчанию.
- Каждая новая функция получает тест; каждый пофикшенный баг — регрессионный тест.
- Coverage-порог: 80% на app/ (бизнес-логика), обеспечивается CI/гейтом, не по желанию агента.

## Security baseline (обязательно, не зависит от tier)

- Сервис слушает только 127.0.0.1 — не 0.0.0.0 — это часть модели угроз (single local user).
- Пользовательский текст в DOM — только через `textContent`, никогда `innerHTML`.
- Имя загруженного файла от клиента никогда не используется как путь на диске
  (temp-файл получает фиксированный суффикс, а не имя из запроса).
- Никаких секретов/API-ключей в репозитории; `uvicorn` без `reload`/debug-трейсбеков в
  ответах — обработчик ошибок не должен возвращать внутренние пути/трассировки клиенту.
- Сущностей с состоянием и удалением в сервисе нет (stateless request/response) — пункт
  "cleanup при удалении" неприменим; temp-файлы аудио удаляются в `finally` после обработки.
